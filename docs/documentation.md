# Documentation

Use one H1, a short purpose, linked navigation, short sections and language-tagged code fences.
Use ordinary relative Markdown links and GFM for GitHub pages. Keep Obsidian wikilinks in vault
templates only. Architecture diagrams need a readable text alternative when complex.

Each topic has one authoritative page; other repositories link to it. Verify commands and links.
Distinguish implemented behavior, planned work, unavailable checks and measured evidence.
Never publish private endpoints, allowlists, secret-bearing URLs, full request logs or personal
facts merely because they appear in a local document. Do not invent experience, projects or metrics.
