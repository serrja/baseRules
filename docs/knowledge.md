# Knowledge and templates

Read the existing vault's AGENTS, navigation, project.json, plugins and template syntax first.
Back up notes/configuration privately. Preserve paths, IDs, checkboxes, attachments, backlinks,
Canvas and bookmarks. Do not create a replacement vault or mirror-delete cloud objects.

## Installation

Copy selected files from [templates](../templates/obsidian/README.md) into the existing section's
configured template directory. Record the upstream full commit and file hashes in a local
provenance file. Review changes before replacing a managed template; local modifications conflict
instead of being silently overwritten. Do not copy personal notes back into this public source.

In project-scope 1.3, create a note within the chosen section and invoke **Шаблоны раздела**.
The nearest project.json selects home/attachments/templates, with template inheritance from parents.
Use the plugin's supported `{{title}}`/`{{date}}` expansion; remaining placeholders are prompts
for the owner. Add a full vault-path return link to the nearest index, then link the new note
from that index. Mark completion only there. Check actual plugin behavior before claiming GUI success.

## Drive

Use verified cloudFolderUrl IDs, metadata, ownership and effective/inherited permissions before
moving objects. Preserve IDs and access. Personal materials stay private; existing university
sharing is preserved. A shortcut is navigation, not synchronization or a second editable master.
Public templates contain only placeholder folder references. Record real folder links in the vault.

Use the [working-document tree](../templates/work-documents.md) as one reusable outline.
Create actual folders only for existing needs; never invent employers, projects or study content.
